# پلتفرم شبکه پردازان ایده‌بان الماس

نسخهٔ اولِ یک سامانهٔ فارسی و راست‌چین برای معرفی و فروش خدمات فناوری اطلاعات، دریافت درخواست و پیگیری سرنخ‌های فروش.

## وضعیت این نسخه

**فاز اول پیاده‌سازی شده است:** صفحهٔ اصلی، کاتالوگ خدمات و صفحات خدمت، پلن‌ها و قیمت‌گذاری شفاف، فهرست و جزئیات نمونه‌کارهای تأییدشده، فرم مشاوره/پیش‌فاکتور و پنل مدیریت برای خدمات، دسته‌بندی‌ها، پلن‌ها، تعرفه‌ها، نمونه‌کارها و سرنخ‌های فروش.

محتوای اولیهٔ خدمات از شرح ارائه‌شده تهیه شده است. هیچ پروژه، نظر مشتری یا نرخ رسمی ساختگی درج نشده است. اگر رکورد قیمت معتبر وجود نداشته باشد، سایت «استعلام قیمت» نشان می‌دهد. تعرفهٔ رسمی تنها با منبع، لینک و وضعیت تأییدشده نمایش داده می‌شود. برای مطالعات موردی، مدیر می‌تواند پیوند HTTPS تصویر و ویدیو را ثبت کند؛ فایل ویدیویی بزرگ روی سرور اصلی بارگذاری نمی‌شود.

### موارد خارج از فاز اول

وبلاگ و مرکز ویدیو، فروش دوره و آکادمی، پنل مشتری، سفارش/قرارداد/فاکتور، پرداخت آنلاین، تیکت، آپلود فایل و ارسال ایمیل در این نسخه پیاده‌سازی نشده‌اند. جداول و مسیر توسعهٔ این قابلیت‌ها در معماری مشخص شده‌اند؛ دکمهٔ غیرعملیاتی برای آن‌ها در سایت نمایش داده نمی‌شود. فرم فعلی سرنخ را در MySQL ذخیره می‌کند و در پنل فروش نمایش می‌دهد. برای اعلان ایمیلی باید SMTP جداگانه پیکربندی و اضافه شود.

## فناوری

- PHP 8.2 یا بالاتر
- MySQL 8.0+ یا MariaDB 10.6+
- افزونهٔ PHP `mysqli` و درایور `mysqlnd` (برای `mysqli_stmt::get_result`)
- رابط سروررندرشده و بدون کتابخانه/CDN خارجی
- معماری MVC ماژولار؛ دسترسی به دیتابیس با prepared statementهای MySQLi

> اگر الزام MySQLi برداشته شود، Laravel انتخاب مناسب‌تری برای رشد ماژول‌های تجارت الکترونیک و پنل مشتری است. این نسخه با توجه به درخواست، MySQLi را مستقیماً استفاده می‌کند.

## راه‌اندازی

۱. یک پایگاه داده و کاربر اختصاصی MySQL بسازید. نمونه (با حساب DBA):

```sql
CREATE DATABASE ideban_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ideban_user'@'localhost' IDENTIFIED BY 'یک-گذرواژه-قوی-و-منحصر-به-فرد';
GRANT SELECT, INSERT, UPDATE, DELETE ON ideban_platform.* TO 'ideban_user'@'localhost';
FLUSH PRIVILEGES;
```

کاربر برنامه فقط مجوزهای خواندن و تغییر داده دارد. ساخت/تغییر جدول‌ها را با حساب DBA یا کاربر مهاجرت جداگانه انجام دهید.

۲. ساختار و محتوای آغازین را با حساب DBA وارد کنید:

```bash
mysql --default-character-set=utf8mb4 -u root -p ideban_platform < database/schema.sql
mysql --default-character-set=utf8mb4 -u root -p ideban_platform < database/seed.sql
```

`schema.sql` نسخهٔ پایهٔ فاز اول است. پیش از اجرای seed، جدول‌ها باید ایجاد شده باشند.

۳. فایل تنظیمات را بسازید و مقادیر واقعی را جایگزین کنید:

```bash
cp .env.example .env
```

`APP_URL` را با دامنهٔ HTTPS واقعی و `DB_*` را با مشخصات دیتابیس تنظیم کنید. فایل `.env` بیرون از document root قرار دارد و نباید در مخزن عمومی منتشر شود. در سرور واقعی `APP_DEBUG=0` بماند.

۴. وب‌سرور را طوری تنظیم کنید که **document root برابر پوشهٔ `public/`** باشد. برای Apache، `mod_rewrite` و اجازهٔ استفاده از `.htaccess` لازم است. در Nginx، درخواست‌های غیر فایل را به `/index.php` بازنویسی کنید و فایل‌های `.env`، `database/` و `app/` را از دسترس عمومی خارج نگه دارید.

۵. مدیر اولیه را از خط فرمان بسازید:

```bash
php bin/create-admin.php
```

نام، ایمیل و گذرواژهٔ قوی وارد می‌شود. حساب پیش‌فرض یا گذرواژهٔ ثابت در کد وجود ندارد. برای نقش‌های فروش و ویرایش محتوا می‌توانید کاربر بسازید و نقش‌های `sales` یا `editor` را در جدول‌های `users`، `roles` و `user_roles` با دسترسی دیتابیس مدیریت کنید.

۶. اتصال و جداول را بررسی کنید:

```bash
php bin/health-check.php
php tests/run.php
```

اجرای محلی (در صورت نصب PHP و MySQL):

```bash
php -S 0.0.0.0:8000 -t public public/router.php
```

## مسیرهای مهم

- `/` صفحهٔ اصلی
- `/services` کاتالوگ خدمات
- `/services/{slug}` صفحهٔ خدمت
- `/pricing` پلن‌ها و تعرفه‌ها
- `/portfolio` نمونه‌کارهای قابل انتشار
- `/portfolio/{slug}` مطالعهٔ موردی
- `/contact` ثبت درخواست مشاوره/پیش‌فاکتور
- `/admin/login` ورود مدیریت
- `/sitemap.xml` نقشهٔ سایت پویا
- `/robots.txt` تنظیمات خزنده‌ها

## نقش‌ها و دسترسی‌ها

- `admin`: همهٔ بخش‌های مدیریت
- `sales`: داشبورد و مدیریت سرنخ‌ها
- `editor`: خدمات، دسته‌بندی‌ها، پلن‌ها و نمونه‌کارها

دسترسی در هر مسیر سمت سرور کنترل می‌شود. کاربر عادی فقط می‌تواند فرم عمومی را ارسال کند؛ پنل مشتری و حساب عمومی هنوز در این فاز وجود ندارد.

## اصول قیمت و انتشار

- مبلغ‌ها با عدد صحیح و به **تومان** ثبت می‌شوند؛ هزینهٔ راه‌اندازی، دوره‌ای (با بازه مثل ماهانه/سالانه) و سایر هزینه‌ها جداگانه قابل ثبت‌اند.
- برای ثبت تعرفهٔ رسمیِ تأییدشده، سال، عنوان منبع و لینک HTTP/HTTPS الزامی است.
- تعرفهٔ رسمیِ تأییدنشده از صفحهٔ عمومی حذف می‌شود؛ قیمت پیشنهادی شرکت و قیمت توافقی برچسب جدا دارند.
- برای مخفی‌کردن رکورد قیمت قدیمی، از دکمهٔ «مخفی‌کردن» در پنل استفاده کنید؛ رکورد جدید را جداگانه ثبت کنید.
- یک نمونه‌کار تنها وقتی عمومی می‌شود که هر دو گزینهٔ «مجوز انتشار» و «انتشار عمومی» فعال باشند.
- قبل از انتشار عمومی، متن قیمت‌ها، محدودهٔ خدمات، رضایت‌نامه و شرایط حقوقی/حریم خصوصی را شرکت بازبینی کند.

## امنیت و عملیات

- فرم‌های تغییردهنده دارای CSRF token، اعتبارسنجی سمت سرور و prepared statement هستند.
- خروجی‌های دیتابیس در قالب HTML escape می‌شوند؛ نشست با `HttpOnly` و `SameSite=Lax` تنظیم می‌شود و در HTTPS، cookie امن است.
- فرم عمومی honeypot و محدودسازی سادهٔ نشست‌محور دارد. برای ترافیک تولیدی، محدودسازی IP/لبهٔ شبکه (مثلاً در وب‌سرور یا WAF) نیز پیشنهاد می‌شود.
- فایل‌های محرمانه یا بارگذاری‌های عمومی در این فاز نگهداری نمی‌شوند. رمز، کلید یا دسترسی سرور را در فرم تماس وارد نکنید.
- بکاپ دیتابیس را رمزگذاری کنید و بازیابی را دوره‌ای آزمایش کنید. کاربر دیتابیس تولیدی را با کمترین مجوز لازم اجرا کنید.

## ساختار پوشه‌ها

```text
app/                 هسته، کنترلرها و قالب‌های PHP
bin/                 ابزار ساخت مدیر و بررسی نصب
database/            ساختار و داده‌های اولیهٔ MySQL
public/              تنها document root عمومی و فایل‌های CSS/JS
preview/             پیش‌نمایش استاتیک رابط کاربری
tests/               آزمون‌های سادهٔ اعتبارسنجی
.env.example         الگوی متغیرهای محیطی
```

## پیش‌نمایش

پوشهٔ `preview/` فقط نمونهٔ استاتیک رابط کاربری است؛ فرم آن عمداً اعلام می‌کند که اطلاعات را ذخیره نمی‌کند. نسخهٔ اجرایی PHP پس از نصب PHP، MySQL و تنظیم `.env` فرم را واقعاً در پایگاه داده ثبت می‌کند.
